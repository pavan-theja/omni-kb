\#\# Platform Overview

\`zs\_observe\` is the \*\*observation/ingestion layer\*\* of ZenStatement — a multi-tenant financial reconciliation platform. This schema stores raw-plus-normalized source data from third-party OMS systems, marketplaces, payment gateways, and settlement files before they flow into the reconciliation processor layers .

\*\*Core business:\*\* ZenStatement ingests seller/merchant transaction data from multiple channels, normalizes it into a common schema, and reconciles it against bank statements, payment gateway settlement files, and marketplace payouts to detect discrepancies, missing payments, or double settlements.

\#\# Table 1: \`mpl\_oms\_withdrawal\`

\#\#\# Business Context

\*\*What is MPL?\*\* Mobile Premier League (MPL) is a global real-money skill-gaming platform with 100M+ users. Players deposit cash into their MPL wallet, play games/tournaments, win cash prizes, and withdraw winnings.

\*\*What is this table?\*\* This table captures \*\*outward money movements\*\* from MPL's Order Management System — specifically when players withdraw their winnings from the MPL wallet to external accounts (bank, PayPal, Skrill, etc.).

\*\*Flow:\*\* Player wins → winnings credited to MPL wallet → Player initiates withdrawal → Payment gateway processes payout → Record lands here with SUCCESS/FAILED status.

\* \`amount\` vs \`abt\_amount\`: \`amount\` is what the player requested; \`abt\_amount\` is what was actually transferred after any processing fees.

\* KYC is mandatory before withdrawals; failed KYC \= \`FAILED\` status.  
\* Daily withdrawal limits: US \= $200/day (max $50 per txn, 10 txns/day); India \= ₹1 lakh/month.  
\* \`zen\_sheet\_name\` \= \`"oms withdrawal"\`.

\#\#\# Reconciliation Use Cases

\* Match withdrawal records against bank outflow statements.  
\* Detect withdrawals that are \`SUCCESS\` in OMS but not reflected in bank debit.  
\* Identify duplicate withdrawal requests (same reference\_id, amount, date).  
\* Audit gateway-wise payout volumes and failure rates.

\#\# Table 7: \`amazon\_gc\_settlement\`

\#\#\# Business Context

\*\*What is this table?\*\* Amazon's periodic \*\*settlement report\*\* for gift card sales — detailing each order line, the principal amount, commissions, fees, TCS (Tax Collected at Source), TDS (Tax Deducted at Source), and net settlement amounts paid by Amazon to the seller (Qwikcilver).

\*\*Settlement Cycle:\*\* Amazon settles sellers every 7–14 days with a consolidated report. Each row represents one order item in one settlement period.

\#\#\# Key Columns

| Column | Type | Business Meaning |  
|--------|------|------------------|  
| \`settlement\_id\` | varchar | Amazon's settlement batch identifier |  
| \`settlement\_date\` | timestamp | Date of settlement |  
| \`created\_date\` | timestamp | Transaction/order date |  
| \`order\_id\` | varchar | Amazon order ID (e.g. \`403-6612367-5153132\`) |  
| \`item\_id\` | varchar | Amazon order item ID |  
| \`sku\_id\` | varchar | Product ASIN/SKU |  
| \`other\_id\` | varchar | Settlement line item reference |  
| \`metadata\` | timestamp | Order creation timestamp |

| \`transaction\_type\` | varchar | \`Order\`, \`Refund\`, \`Adjustment\`, \`FBAFee\` |  
| \`quantity\` | integer | Number of units  |  
| \`fulfillment\_channel\` | varchar | \`MFN\` (Merchant Fulfilled) or \`AFN\` (Amazon Fulfilled) |

| \`charged\_amount\` | numeric | Principal amount |  
| \`item\_fee\_type\` | varchar | \`Commission\`, \`FBAFee\`, \`ShippingChargeback\` |  
| \`item\_fee\_amount\` | numeric | Fee amount (negative \= deduction) |  
| \`item\_fee\_tax\` | numeric | GST on the fee (negative) |  
| \`total\_tcs\_amount\` | numeric | Total TCS deducted by Amazon |  
| \`total\_tds\_amount\` | numeric | Total TDS deducted by Amazon |

| \`reimbursement\_charges\` | numeric | Amazon reimbursements (if any) |  
| \`reimbursement\_type\` | varchar | Type of reimbursement |  
| \`shipment\_fee\_amount\` | numeric | Shipping fee charged/credited |

| \`settled\_amount\` | numeric | Net amount after all deductions |  
| \`currency\_type\` | varchar | Null (using INR by default) |

\#\#\# Net Settlement Formula

\`\`\`  
settled\_amount \= charged\_amount \+ item\_fee\_amount \+ item\_fee\_tax \+ total\_tcs\_amount \+ total\_tds\_amount \+ other\_transaction\_fees \+ reimbursement\_charges \+ shipment\_fee\_amount  
\`\`\`

\#\#\# Business Rules & Notes

\* \`item\_fee\_amount\` and \`item\_fee\_tax\` are \*\*negative\*\* (deductions from principal).  
\* \`total\_tcs\_amount\` \= TCS at 0.1% under Section 206C(1H) for gift cards.  
\* \`total\_tds\_amount\` \= TDS under Section 194O (1% for digital commerce).  
\* \`transaction\_type \= 'Refund'\` rows have negative \`charged\_amount\`.  
\* \`transaction\_type \= 'Adjustment'\` \= Amazon corrections, chargebacks, promotional credits.  
\* \`fulfillment\_channel \= 'MFN'\` \= Qwikcilver fulfills (gift card activation). Not Amazon warehoused.  
\* Gift card ASIN: \`B00RFJTSEI\` \= Amazon Pay eGift Card.  
\* Settlement ID is shared across hundreds of line items — it's a batch identifier.

\#\#\# Reconciliation Use Cases
