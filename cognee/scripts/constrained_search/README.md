# Constrained Search Cognee Ingestion

SDK-style ingestion wrappers for the constrained-search pack generated by:

```bash
.venv/bin/python build/constrained_search/build_refactored_v2.py --profile marketplace_runtime --clean
```

The scripts read the generated pack directly. They do not rebuild cards and do
not use the current repo's plain HTTP ingestion path.

Root Python files are stable CLI entrypoints. The ingestion implementation lives
under `ingestion_runtime/`:

```text
add_batches.py        -> ingestion_runtime.add_batches
cognify_batches.py    -> ingestion_runtime.cognify_batches
ingestion_probe.py    -> ingestion_runtime.ingestion_probe
search_trace.py       -> search_runtime.search_trace
nodeset_recall_probe.py -> search_runtime.nodeset_recall_probe
runtime_env.py        -> shared constrained-search environment setup
```

By default the wrappers load `cognee/.env` and use `--provider auto`. Auto
honors `COGNEE_LLM_PROVIDER` / `COGNEE_EMBEDDING_PROVIDER` first, then falls
back to Azure when Azure keys are present. Use `--provider vertex` to force the
Vertex path, or `--provider azure` to force Azure.

Pass `--env-file` for the active runtime. The constrained wrappers apply the
full local Cognee runtime from that file: Postgres, Neo4j, Qdrant, auth posture,
connection-test behavior, logging, model provider, embedding dimensions, and
Google credentials. Docker-shaped `host.docker.internal` values are translated
to `localhost` for local script runs, while pack-local runtime directories under
`cognee_runtime/` always win over `/app/...` values from the env file.

Live add requires a Cognee SDK that accepts `node_set` on `cognee.add`.
Live probe defaults to targeted `cognee.recall(..., only_context=True)` with
`node_name=[...]` and `node_name_filter_operator="AND"`. It routes each probe
contract to the dataset shard that contains the expected card by reading
`cognee_ingestion/add_batches.jsonl`, avoiding all-shard completion calls.
Pass `--mode search-completion` to use the older completion-style search probe,
or `--all-datasets` to deliberately disable shard routing.

## Run

```bash
.venv/bin/python cognee/scripts/constrained_search/add_batches.py \
  --pack-dir build/constrained_search/build \
  --env-file cognee/.env.vertex.gemini352 \
  --provider vertex

.venv/bin/python cognee/scripts/constrained_search/cognify_batches.py \
  --pack-dir build/constrained_search/build \
  --env-file cognee/.env.vertex.gemini352 \
  --provider vertex

.venv/bin/python cognee/scripts/constrained_search/ingestion_probe.py \
  --pack-dir build/constrained_search/build \
  --env-file cognee/.env.vertex.gemini352 \
  --provider vertex
```

## What Each Step Does

`add_batches.py` reads `cognee_ingestion/add_batches.jsonl`, validates every
document path and NodeSet list, then calls:

```python
cognee.add(
    data=batch["doc_paths"],
    dataset_name=batch["dataset_name"],
    node_set=batch["node_sets"],
)
```

It writes `cognee_ingestion/add_manifest.jsonl`.

`cognify_batches.py` reads `cognee_ingestion/cognify_batches.jsonl`, then calls:

```python
cognee.cognify(datasets=batch["datasets"])
```

It writes `cognee_ingestion/cognify_manifest.jsonl`.

`ingestion_probe.py` reads `resolver_catalog/`, validates the generated NodeSet
contracts, routes each contract to the relevant shard, probes recall context,
and writes:

```text
traces/cognee_ingestion_probe_result.json
```

Use `--dry-run` on any script to validate inputs without calling the Cognee SDK.

## Manual NodeSet Recall Probe

`nodeset_recall_probe.py` runs fixed, known-good recall contracts across
platform, table, account data binding, column, metric, reconciliation profile,
tenant, and group runtime cards. It is meant to verify the populated Cognee
dataset before we test open-ended search planning.

Dry-run contract validation:

```bash
.venv/bin/python cognee/scripts/constrained_search/nodeset_recall_probe.py \
  --pack-dir build/constrained_search/build \
  --env-file cognee/.env.vertex.gemini352 \
  --provider vertex \
  --dry-run
```

Live recall:

```bash
.venv/bin/python cognee/scripts/constrained_search/nodeset_recall_probe.py \
  --pack-dir build/constrained_search/build \
  --env-file cognee/.env.vertex.gemini352 \
  --provider vertex
```

It writes:

```text
traces/manual_nodeset_recall_probe_result.json
```

## Search Runtime

`search_trace.py` runs the scaffolded constrained-search loop against the pack:

```text
query
  -> LLM emits validated NodeSet contracts
  -> Cognee recall-context search executes each contract
  -> returned cards are validated against resolver_catalog
  -> trace is written to traces/last_search_trace.json
```

Run a wiring dry-run:

```bash
.venv/bin/python cognee/scripts/constrained_search/search_trace.py \
  --pack-dir build/constrained_search/build \
  --query "Amazon settlement cash position for this group" \
  --dry-run
```

Run an LLM planning dry-run. This calls the built-in Vertex/LiteLLM JSON
provider, validates and routes emitted NodeSet contracts, and stops before
Cognee recall:

```bash
.venv/bin/python cognee/scripts/constrained_search/search_trace.py \
  --pack-dir build/constrained_search/build \
  --env-file cognee/.env.vertex.gemini352 \
  --provider vertex \
  --query "Amazon settlement cash position for this group" \
  --tenant-id tenant.mensa_brand_technologies_private_limited \
  --group-id group.mensa_brand_technologies_private_limited.g8.gl22 \
  --llm-dry-run
```

Live search uses the same built-in Vertex/LiteLLM JSON provider unless
`--llm-callable` is supplied:

```bash
.venv/bin/python cognee/scripts/constrained_search/search_trace.py \
  --pack-dir build/constrained_search/build \
  --env-file cognee/.env.vertex.gemini352 \
  --provider vertex \
  --query "Amazon settlement cash position for this group" \
  --tenant-id tenant.mensa_brand_technologies_private_limited \
  --group-id group.mensa_brand_technologies_private_limited.g8.gl22
```

Search defaults to targeted `cognee.recall(..., only_context=True)` with
NodeSet filters and add-batch dataset routing. Use `--all-datasets` only when
you deliberately want to disable routing.
